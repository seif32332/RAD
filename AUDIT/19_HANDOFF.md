## 4. الخطة المعتمدة باختصار (التفاصيل في v2)

- **P0 (R1، إصدار بنية):** 0A حفظ (تم: الوسم والفرع) → 0B دفع → CI → 0C تصنيف كل إخفاق (environmental / test defect / existing defect / regression / migration issue / security issue) → 0D مرشح إصدار → staging → **تمرين على نسخة شركة حقيقية** (استعادة → ترحيل → مطابقة → تحقق → تمرين رجوع). الرجوع = كل شيء أو لا شيء (نسخة واحدة قبل النشر). ليس إطلاقاً للمنتج.
- **P1 (تجربة ظل):** شركة حقيقية، مسير موازٍ، رديف ليس النظام الرسمي. يحتاج فقط ما يحتاجه المسير الموازي (OD-6).
- **P2 (تجربة تشغيلية):** الشركة تستخدم رديف فعلياً بنطاق متفق عليه ورجوع واضح.
- **P3 (إطلاق عام):** أي شركة مؤهلة. ملف WPS هنا بدليل «Bank-spec validated + عينة بنك حقيقي» (OD-7).

## 7. طريقة العمل (يجب الحفاظ عليها)

- **قبل أي كود:** قراءة الدستور والإجابة عن الأسئلة الستة. لا تعديل للدستور إلا بـADR يوافق عليه المالك.
- **توجيه الوكلاء** (`.claude/agent-routing.md`، حارس آلي يرفض وكيلاً عاماً بلا نموذج): Opus للمال والنطاق والصلاحيات والقيم القانونية وترحيلات البيانات والتصميم؛ Sonnet للتنفيذ المحسوم والاختبارات؛ Haiku للبحث.
- **لكل حزمة أمان أو مال:** مراجعة أمان مستقلة بعدسة واحدة حتى «closed»، وكل ثغرة باختبار يفشل قبل الإصلاح.
- **الفحص قبل كل commit:** حاوية postgres:16 مؤقتة → `npx prisma migrate deploy` → فحص الانحراف `npx prisma migrate diff --from-url $DATABASE_URL --to-schema-datamodel prisma/schema.prisma --exit-code --script` → `npm run typecheck` → `npm run lint` → `npx vitest run` مرتين بالأعلام `PLATFORM_IT EFF_IT SCOPE_IT ONBOARDING_IT INV_IT JOBS_IT LCY_IT CAL_IT RULE_IT PAY_IT WFE_IT` مع `UPLOAD_DIR`، **مع حفظ المخرجات الكاملة**.
- **لا تلمس** حاويات الجلسات الأخرى (`rr`، `pgshadow`) ولا تعِد تشغيل Docker Desktop. جلسة أخرى تعمل على `src/lib/documents` و`src/app/documents`.
- **الحفظ:** commits محلية بأسطر العمل فقط؛ الدفع بقرار المالك.
- **الدفع من هذه البيئة لا يعمل:** مفتاح SSH غير محمّل (`Permission denied (publickey)`) و`gh` غير مثبت. المالك يدفع من طرفيته (PowerShell 5.1: لا `&&`).
