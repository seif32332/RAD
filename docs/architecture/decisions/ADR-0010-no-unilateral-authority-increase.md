# ADR-0010: no individual can unilaterally increase financial authority

- **التاريخ:** 2026-10-03
- **الحالة:** ACCEPTED (تعليمات المالك 2026-10-03، DEC-PO-145).
- **المشكلة:** BL-PAY-005 وBL-PAY-017/022 وBL-PAY-021 أغلقت سبعة مسارات يرفع بها شخص واحد صلاحيته المالية بنفسه (حساب وهمي يُقَرّ به، تغيير البريد ثم الإقرار، حساب قديم مجهول المنشئ، إنهاء خدمة المعتمد الآخر، تضييق نطاق شركاته، …). كل مسار أُغلق بفحص في موضعه، ولا ثابت دائم يمنع عودة المسار نفسه من واجهة أو مسار آخر.

## القرار

1. ARCHITECTURE_INVARIANTS §4.2.1 يُضاف **INV-IAM-01**:
   > لا يستطيع فرد واحد أن يرفع صلاحيته المالية بنفسه بتغيير عضوية الشركات، أو صفة المعتمد، أو الدور، أو حالة الحساب.

   الطبقة: بوابة (جداول الهوية وأعمدتها محمية؛ كل تغيير يُنزل شركة تحت معتمدَين محتسبَين يحتاج معتمداً ثانياً) + اختبارات انحدار دائمة. الخطورة: BLOCKING. يوقف: نعم (المال).
2. اختبارات الانحدار الدائمة لـ INV-IAM-01، لا تُحذف ولا تُضعف إلا بقرار ADR:
   - `src/app/api/settings/__tests__/identity.scope.it.test.ts` (2a–2e، 4a، 4b)
   - `src/modules/iam/__tests__/x-security-identity.test.ts`
   - `src/modules/iam/__tests__/x-security-root.test.ts`
   - `src/modules/iam/__tests__/controls-acceptance.it.test.ts` (خروج المعتمد)
   - `src/modules/iam/__tests__/scope-controls.it.test.ts` (نطاق الشركات)
   - `src/modules/iam/__tests__/identity-contention.test.ts`
3. ARCHITECTURE_INVARIANTS §4.4 (تعريف الإنجاز) يُضاف بند: كل تغيير يمس الهوية أو الأدوار أو نطاق الشركات أو حالة الحساب أو احتساب المعتمدين يثبت INV-IAM-01 باختبار انحدار يحاول المسار بشخص واحد ويفشل قبل الإصلاح.

## العواقب

- أي مسار جديد يكتب في جداول الهوية أو أعمدتها يمر بوحدة iam (البوابة ترفض غيره)، ويضيف اختبار INV-IAM-01.
- محرك الموافقات (الحزمة B) يقرأ أهلية المعتمد من iam ولا يتجاوزها.
