# 4. الثوابت المعمارية وثوابت البيانات

نوعان من الثوابت:
- **ARCH**: قواعد في **شكل الكود**، تحرسها اختبارات المطابقة المعمارية في CI.
- **INV**: قواعد في **البيانات**، يحرسها محرك المصالحة وقيود قاعدة البيانات.

## 4.0 معنى "صفر اختلافات"

> **الهدف: صفر اختلافات جوهرية غير مشروحة (Zero unexplained material discrepancies).**

النظام الطبيعي يحتوي على فروق مشروعة: تقريب، وتسويات رجعية، وتصحيحات متأخرة، ومعاملات ملغاة، وفروق توقيت مع أنظمة خارجية كالبنك وGOSI. المطلوب أن **يُصنَّف كل فرق** في إحدى ثلاث حالات:

| الحالة | المعنى | مثال |
|---|---|---|
| **EXPECTED** | فرق متوقع بقاعدة معروفة، يُسجل ولا يُنبَّه عليه | تقريب هللة ضمن الحد المسموح، سطر فرق رجعي مرتبط بسببه |
| **EXPLAINED** | فرق حقيقي له شرح مسجَّل وفاعل ومرجع | البنك رفض تحويلاً لآيبان مغلق، ومعه رقم الرد |
| **RESOLVED** | فرق صُحح بعملية في النظام | قيد تصحيح أو إعادة إصدار |

وأي فرق خارج هذه الحالات الثلاث **اختلاف مفتوح**.

## 4.1 ثوابت المطابقة المعمارية (ARCH)

### 4.1.1 القائمة

### 4.1.2 طريقة التنفيذ (بلا اعتماديات جديدة)

- اختبارات Vitest في `src/test/architecture/*.arch.test.ts` تستخدم **TypeScript Compiler API**، وهي موجودة لأن `typescript` اعتمادية قائمة، لتحليل الاستيرادات والنداءات.
- قواعد ESLint `no-restricted-imports` و`no-restricted-syntax` للفحوص الرخيصة، مع ظهور فوري في المحرر.
- امتدادات Prisma وقت التشغيل للإنفاذ الفعلي (البوابة، النطاق)، والفحص الثابت للتنبيه المبكر.

### 4.1.3 السقّاطة (Ratchet)

الكود الحالي يخالف كثيراً من هذه القواعد. لذلك:

- ملف `src/test/architecture/baseline.json` يسجل المخالفات الموروثة: قاعدة، ملف، وعدد.
- الاختبار **يفشل عند أي مخالفة جديدة**، أو عند زيادة عدد مخالفات ملف موجود.
- حين تنقص المخالفات يجب تحديث الخط الأساسي في نفس التغيير، فلا يرجع العدد للأعلى.
- لا يجوز إضافة مدخل للخط الأساسي إلا بقرار ADR.
- **المدخلات المجازة:** ARCH-003 للاشتقاق الاحتياطي `employmentState ?? (isTerminated…)` (BR-LCY-013) داخل قرّاء lifecycle فقط، ويُحذف في Release C (ADR-0002 #5).

## 4.3 نموذج الاختلاف (Discrepancy)

```text
Discrepancy
  id
  fingerprint        UNIQUE  -- ruleId + entityType + entityId + period: الاكتشاف المكرر يحدّث لا يضيف
  ruleId                     -- INV-PAY-01 …
  domain
  companyId
  entityType, entityId
  period                     -- YYYY-MM أو daterange
  severity                   -- INFO | WARNING | HIGH | BLOCKING
  blocking   BOOLEAN         -- يُحسب من الخطورة وسياسة الشركة، ويُخزَّن وقت الاكتشاف
  expectedValue  JSON
  actualValue    JSON
  delta          JSON        -- الفرق المحسوب
  category                   -- UNCLASSIFIED | EXPECTED_ROUNDING | EXPECTED_RETRO | EXPECTED_TIMING | …
  status                     -- OPEN | EXPLAINED | RESOLVED | WAIVED | AUTO_CLOSED
  detectedAt, lastSeenAt, occurrences
  ownerUserId                -- المسؤول عن المعالجة
  resolution  TEXT
  resolutionRef              -- الكيان أو العملية التي صححته
  resolvedAt, resolvedById
  waivedById, waiverApprovedById   -- التنازل عن BLOCKING يحتاج شخصين
```

### القواعد

1. **الاكتشاف** مهمة `reconcile`: ليلية لكل الثوابت، وفورية لثوابت المسير قبل كل اعتماد. تكتب أو تحدّث بالبصمة. وإذا اختفى الشرط في تشغيل لاحق يصبح الاختلاف `AUTO_CLOSED` مع سجل.
2. **الخطورة:**
   - **ثوابت السلامة ثابتة** (DEC-PO-120، ADR-0001 #11)، ولا تستطيع الشركة تعطيلها أو خفضها: INV-EFF-01، INV-ORG-01، INV-PAY-01..06، INV-GOSI-01، INV-ATT-02، INV-LEV-01، INV-EOS-01، INV-DOC-01، INV-SCOPE-01. والاختلاف فيها يُشرح (EXPLAINED بشخص ثانٍ) أو يُتنازل عنه (WAIVED بشخصين وتنبيه المالك)، وهذه الشروط ليست إعداداً.
   - **مستأجر المشغّل الواحد** (ADR-0002 #1، DEC-PO-122): في SINGLE_OPERATOR للمشغّل الوحيد أن يشرح اختلافاً موقِفاً في ثابت سلامة أو يتنازل عنه، مع تسجيل `SELF_ACT_SINGLE_OPERATOR` وتأكيد صاحب الشركة عبر قناة DEC-PO-022. والتأكيد مانع للملف قبل إرساله إذا كان الثابت INV-PAY-03 (الملف كله، DEC-PO-014). وINV-PAY-05 يُكشف لاحقاً ولا يمنع (DEC-PO-018). الشرح والتنازل ليسا اعتماد مدخل في DEC-PO-005/014، والمستفيد لا يكون أحد شخصَي التنازل عن سطره، والبديل DEC-PO-004.
   - **بقية الثوابت** خطورتها افتراض قابل للتعديل لكل شركة (DEC-PO-116)، مع سجل التغيير وتنبيه المالك عند التخفيف.
3. **البوابة** (L4) تفحص `blocking = true AND status = OPEN` **في نطاق العملية فقط**:
   - اعتماد المسير يوقفه اختلاف blocking يخص تلك الشركة وذلك الشهر.
   - صرف التسوية يوقفه ما يخص ذلك الموظف.
   - اختلاف في تقرير لا يوقف المسير.
4. **فئات EXPECTED** تُغلق آلياً عند إثبات شرطها (مثل تقريب ≤ هللة لكل بند، أو فرق رجعي له سطر فرق مرتبط).
5. **EXPLAINED** يتطلب نصاً ومرجعاً وفاعلاً. وفي BLOCKING يحتاج **شخصاً ثانياً** لرفع الإيقاف، أو يُتنازل عنه (`WAIVED`) بشخصين وتنبيه المالك.
6. **لوحة المالك** تعرض: المفتوح حسب الخطورة، والأقدم، والمتنازل عنه هذا الشهر، ونتيجة آخر تشغيل لكل ثابت.

## 4.4 تعريف الإنجاز المعماري لأي تغيير

لا يُدمج تغيير إلا مع كل ما يلي:

- [ ] **اختبارات ARCH** خضراء، بلا زيادة في الخط الأساسي.
- [ ] **الثوابت** المتأثرة معرفة ومحدثة، والمصالحة على بيانات التجربة **بلا اختلاف مفتوح بخطورة HIGH أو BLOCKING**.
- [ ] **لا وصول بين الشركات:** اختبار النطاق للمسارات الجديدة أو المعدلة.
- [ ] **عدم التكرار:** اختبار الاستدعاء المزدوج (متتابع ومتزامن) لكل انتقال جديد، ويُنتج نفس الحقائق والأحداث والإشعارات.
- [ ] **الترحيل** إما قابل للعكس أو بنمط **توسيع ثم تقليص** (expand/contract). Prisma لا يدعم ترحيلات عكسية، فالرجوع = إصدار سابق + ترحيل توسيع متوافق + نسخة احتياطية مجربة. وخطة الرجوع مكتوبة في وصف التغيير.
- [ ] **إعادة التشغيل:** كل مستهلك أحداث جديد يُعاد تشغيله على نفس الأحداث دون أثر مكرر.
- [ ] **التدقيق:** قيمة قبل وبعد لكل تغيير على حقيقة.
