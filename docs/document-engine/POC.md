# POC — مصيّر Typst لخطاب تعريف بالراتب

**الغرض:** اختبار Typst مصيّراً فقط (ADR DOC-01)، معزولاً عن المحرك وعن كود التطبيق. لا ترحيل ولا تنفيذ إنتاجي قبل نجاح كل المعايير الجوهرية.

**المكان:** `poc/document-renderer/`، خارج `src/` ولا يستورده التطبيق.

**البيئة:**
- Typst `0.15.1` من الصورة الرسمية `ghcr.io/typst/typst@sha256:032e2922…c422f` (Alpine، linux/amd64).
- التشغيل في حاويات Linux على Docker Desktop (8 أنوية، 8 جيجابايت). هذا أقرب ما يتاح لبيئة الإنتاج.
- الفاحص: حاوية Python منفصلة فيها PyMuPDF وfontTools وOpenCV. الفاحص لا يدخل حاوية المصيّر.

**التجهيزات (fixtures):** بيانات اصطناعية لا تخص موظفاً حقيقياً.

| المعرّف | الوصف |
|---|---|
| `F1-ar` | خطاب عربي، اسم عادي، توقيع مفوَّض |
| `F2-ar-en` | ثنائي اللغة، نفس البيانات |
| `F3-long` | ثنائي اللغة، اسم عربي من سبعة مقاطع، واسم إنجليزي طويل، وجهة موجَّه إليها طويلة |
| `F4-unauth` | مثل F1، لكن دون تفويض توقيع |
| `F5-arabnum` | مثل F1، بأرقام عربية مشرقية (٠١٢٣) |
| `F6-stress` | 30 بدلاً في الجدول لإجبار صفحتين |
| `F7-inject` | نصوص تحاكي ترميز Typst في الاسم والجهة (`#read("/etc/passwd")`، `*x*`، `$y$`، `<l>`، `@ref`) |

## النتائج (2026-09-26)

**الحكم: Typst ينجح في كل المعايير الجوهرية بعد ثلاثة تعديلات داخل Typst نفسه، ويُعتمد.** وGotenberg لا يحل أي مشكلة ظهرت، بل يشاركها ويضيف أخرى.

الإعداد النهائي المُختبَر هو نفسه المقترح للإنتاج:

```
typst compile --root <tmp> --font-path <bundle> --ignore-system-fonts --ignore-embedded-fonts
              --creation-timestamp <issuedAt> [--pdf-standard a-2b] main.typ out.pdf
```

مع `#set text(fallback: false)` في القالب، وحزمة خطوط فيها IBM Plex Sans Arabic فقط.

**تعديلات على المعايير بعد التشغيل (شفافية):**
- **AC-02:** كان المستخرج المرجعي PyMuPDF، وتبيّن أنه يعكس المحارف المركبة العربية لأي منتج PDF (§B). المرجع صار xpdf، ومصفوفة poppler وMuPDF تُسجَّل للاطلاع (`INFO-extract`).
- **AC-02 وAC-07 وAC-10 في الصفحات ثنائية اللغة:** المطابقة على مستوى الكلمة لا العبارة، لأن ترتيب المقاطع المختلطة يعيد المستخرج بناءه، وثبت أن Chromium يعطي الترتيب نفسه.
- **AC-04:** فحص الترتيب آلياً للصفحات أحادية الاتجاه فقط، وهندسياً وبصرياً لثنائية اللغة.
- **AC-05:** كلمات مرجعية بدل العبارات، لأن PyMuPDF يدمج علامات الترقيم.

لم يُخفَّف أي معيار بصري أو هندسي.

### D. مشكلات ترقيم الصفحات

لا مشكلة جوهرية. ملاحظات:
- `table.header` يتكرر تلقائياً، و`block(breakable: false)` يمنع قسمة كتلة التوقيع، و`counter(page).final()` يعطي «من ص» صحيحاً في كل صفحة، بالأرقام المشرقية عند طلبها.
- عندما يدفع الجدول الطويل كتلة التوقيع كاملة إلى صفحة جديدة، تبقى مساحة فارغة أسفل الصفحة السابقة. هذا سلوك مقصود.

### F. الأمن والعزل

| الاختبار | النتيجة |
|---|---|
| مستخدم `nobody`، ونظام ملفات للقراءة فقط، و`--cap-drop ALL`، و`no-new-privileges`، و`--pids-limit 64` | يعمل بلا أي كتابة إلا ملف المخرج |
| `#read("/etc/passwd")` | محجوب: المسار المطلق يُحل داخل `--root` |
| `#read("../F1-ar/data.json")` | محجوب: «would escape the project root» |
| `#import "@preview/..."` | فشل لانعدام الشبكة. **Typst يحاول التنزيل من الشبكة** لو وُجد استيراد حزمة، فعزل الشبكة إلزامي، ويُمنع `@preview` في القوالب بفحص CI |
| حقن ترميز في البيانات (F7) | كل النصوص طُبعت حرفياً: `#read`، `#panic`، `$y$`، `*x*`، `#import`، `#{ 1 + 1 }`. لا تنفيذ ولا خطأ |
| لا JavaScript ولا HTML ولا طلبات شبكة ضمنية | بخلاف Chromium، لا سطح SSRF أصلاً |

**مخاطر متبقية:**
- فك الصور (PNG وSVG) داخل Typst سطح هجوم، لأن الشعار والتوقيع والختم يرفعها المستخدم. المعالجة: PNG فقط، وفحص البايتات السحرية والأبعاد قبل الإرسال، والتشغيل في خدمة معزولة (H).
- القالب نفسه كود يمكنه قراءة أي ملف داخل `--root`، فالمجلد المؤقت لا يحتوي إلا ملفات الطلب.

### G. القرار: Typst أم Gotenberg

**Typst.** Gotenberg يبقى محوّلاً ممكناً خلف `DocumentRenderer` دون تنفيذ الآن.

| | Typst | Gotenberg |
|---|---|---|
| المعايير الجوهرية | كلها ناجحة | لم يُختبر كاملاً. يشارك B1 وB3، ويفسد الضمة والشدة |
| الحتمية (golden tests، وإعادة التصيير عند النزاع) | نعم | لا |
| الذاكرة على خادم فيه عملاء متعددون (DEC-004) | ~28 MB عابرة | ~320 MB مقيمة وذروة 749 MB |
| سطح الهجوم | صغير | متصفح كامل |
| الميزة الوحيدة لـGotenberg | — | طبقة نص أفضل للتنوين، وقوالب HTML مألوفة |

الميزة الوحيدة لـGotenberg عالجناها بحذف الحركات، وهي لا تبرر عشرة أضعاف الذاكرة وفقدان الحتمية.

> **فرق عن المخطط أدناه:** الثنائي من إصدار GitHub الرسمي (`typst.lock`)، وبصمته `29273eaa…` لا `908d5a47…` (ثنائي صورة Docker). ثبت أن الاثنين يعطيان بايتات متطابقة لكل التجهيزات.

- **لماذا خدمة جانبية لا `spawn` من عملية العميل:**
  - فك صور يرفعها المستخدم يُعزل عن ملفات العميل وأسراره (`DATA_ENCRYPTION_KEY`).
  - حزمة خطوط واحدة مثبّتة لكل خادم.
  - نفس نمط `radeef-face` وتحصينه.
  - الذاكرة عابرة (~28 MB لكل تصيير)، فلا أثر على DEC-004.
- **التشغيل:** وحدة systemd منسوخة من `ops/systemd/radeef-face.service`، مع:
  - `DynamicUser`، و`IPAddressDeny=any` + `IPAddressAllow=localhost`، و`InaccessiblePaths` لبيانات العملاء، و`PrivateTmp`، و`MemoryMax=512M`، و`TasksMax=64`.
  - الرمز في `/etc/radeef/services/render.env`، وليس `/etc/radeef/*.env` الذي يُعامل كعميل.
  - ولنشر Docker (DEC-004 B): نفس الخدمة في حاوية `--network none` بمقبس Unix.
- **الخدمة عامة:** Node دون تبعيات، وثنائي Typst 0.15.1 مثبّت بالبصمة (`sha256:908d5a47…4c6be9`)، وحزمة الخطوط. لا تحتوي قوالب ولا منطق مستندات.
- **القوالب في رديف** (`src/lib/documents/templates/`) وتُرسل مع كل طلب، فيعرف المحرك بصمتها بالضبط (DOC-07). يلزم `outputFileTracingIncludes` في `next.config` حتى تدخل ملفات `.typ` في بناء standalone.
- **ما يُحفظ على المستند (DOC-07):**
  - `rendererId = typst`
  - `rendererVersion = 0.15.1`
  - `fontsSha256` من رأس الاستجابة
  - `pdfStandard = a-2b`
  - `creationTimestamp = issuedAt`، وهذا ما يجعل إعادة التصيير تطابق البصمة.
- **فحوص CI:**
  - اختبارات golden: كل قالب × لغة × تجهيزة ← بصمة ثابتة.
  - هذا الفاحص نفسه (`harness/check.py`) على التجهيزات.
  - منع `@preview` و`read(`/`sys.inputs` خارج الملفات المسموحة في القوالب.
  - إضافة خط أو ترقية Typst تكسر golden عمداً، وتحتاج مراجعة بصرية.

### I. تغييرات مطلوبة على SPEC وADR

طُبّقت في هذا التسليم:

1. **ADR DOC-01:**
   - خطوة **نموذج العرض (render model)** إلزامية بين اللقطة والمصيّر. اللقطة قيم قانونية، والنموذج نصوص عرض.
   - المصيّر لا ينسّق شيئاً.
   - فحص التغطية.
   - التحذيرات تُعامل كأخطاء.
2. **ADR DOC-07:** إضافة `pdfStandard`، و`creationTimestamp = issuedAt`، وتعريف `rendererVersion` و`fontsSha256`.
3. **SPEC §3:**
   - نتيجة القرار، والأعلام، والحزمة: Plex ثابت فقط، وNoto Naskh مرفوض.
   - الخدمة الجانبية وواجهتها (H).
4. **SPEC §4.2:**
   - سياسة الحركات.
   - قواعد القوالب: `fallback: false`، ولا حزم، ولا أسماء لاتينية طويلة في نص عربي جارٍ، ونص ثابت بلا حركات.

7. **SPEC §15:** قرار مالك جديد: حذف التشكيل من الأسماء المطبوعة.
